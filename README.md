# 企业销售报表自动化工具

把「每周手工整理销售报表」这件事固化成一个脚本：把一个 Excel 放进项目目录，运行一次，得到 8 个工作表和 3 张图表的经营报表。

> 这是一个模拟真实委托的练习项目，用于验证「把业务问题变成可交付成果」的完整流程：需求 → 实现 → 测试 → 文档。

---

## 它解决什么问题

小型商贸公司的销售订单全部记在 Excel 里。每到周末，销售内勤要手工筛选、复制、求和，整理出总销售额、各产品销量、各销售员业绩和月度趋势，前后要花一两天。

三个痛点：**慢**、**容易算错**、**下个月还要重来一遍**。

这个工具把这套固定动作固化下来，并且保证：每次算出来的口径都一样，出错时能定位到原始表的具体行。

---

## 功能

| 模块 | 说明 |
|---|---|
| 字段校验 | 检查 10 个必需字段，缺失时中断并指明少了哪一列 |
| 数据体检 | 缺失值、整行重复、订单号重复、订单号为空、日期无效、数值无法解析、单价 ≤ 0、数量 ≤ 0、金额不符 |
| 数据清洗 | 去重、剔除无效行、统一数据类型，并打印丢弃行数 |
| 多维汇总 | 总览、按月份、按区域、按产品、按销售员、客户 TOP10 |
| 图表 | 月度销售额柱状图、区域占比饼图、销售员业绩柱状图 |
| 报表导出 | 多工作表、表头样式、冻结首行、自动列宽、数字格式 |

**处置原则**：结构性错误（缺字段）中断运行；数据性问题（空值、异常、重复）继续运行并输出问题清单，附原始行号。

## 快速开始

```bash
# 1. 创建虚拟环境（Windows）
python -m venv venv

# 2. 安装依赖
.\venv\Scripts\python.exe -m pip install pandas openpyxl

# 3. 把订单表放到项目根目录，命名为 销售订单.xlsx

# 4. 运行
.\venv\Scripts\python.exe main.py
```

运行完成后，项目根目录会生成 `销售报表.xlsx`。

> 用解释器的完整路径调用，不依赖 PATH 与激活状态，行为更确定。

---

## 输入格式

一个 `.xlsx` 文件，第一个工作表，首行为表头，包含以下 10 列：

| 列名 | 类型 | 说明 |
|---|---|---|
| 订单号 | 文本 | 同一订单多行明细时允许重复 |
| 下单日期 | 日期 | 支持日期或可解析的文本 |
| 客户名称 | 文本 | |
| 区域 | 文本 | |
| 产品编码 | 文本 | |
| 产品名称 | 文本 | |
| 单价 | 数值 | |
| 数量 | 数值 | |
| 金额 | 数值 | 应等于 单价 × 数量 |
| 销售员 | 文本 | |

---

## 输出内容

`销售报表.xlsx`，共 8 个工作表：

| 工作表 | 内容 |
|---|---|
| 总览 | 总销售额、订单数、销量、客户数、客单价、数据区间 |
| 数据质量 | 20 项检查及各自的问题行数 |
| 按月份 | 每月销售额、环比、占比，含合计行与柱状图 |
| 按区域 | 各区域销售额、客单价、占比，含饼图 |
| 按产品 | 产品排名与占比 |
| 按销售员 | 业绩对比，含柱状图 |
| 客户TOP10 | 前十大客户 |
| 明细 | 原始订单倒序 |

若数据存在问题，会额外生成「问题数据」工作表，含**原表行号**与**问题说明**。

## 已知限制

- 金额与「单价 × 数量」不符的行**仅标记、不剔除**，仍会计入汇总。建议下一版改为可配置。
- 日期为文本且无法解析时整行会被丢弃，存在静默丢数的可能。
- 仅读取第一个工作表，不支持多表或多文件合并。
- 不支持合并单元格、多级表头等非标准格式。
- 无运行日志，排错依赖控制台输出。
- 需要本地 Python 环境，尚未打包为可执行文件。
